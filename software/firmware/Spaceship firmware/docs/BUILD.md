# Сборка прошивки

Сборка использует локальную копию z88dk 2.4, sccz80 в режиме Intel 8080, библиотеку DAI32 и собственный CRT часов с распаковщиком ZX7 для 8080. Системный PATH не меняется.

## Подготовка среды

На этом компьютере уже доступны Python 3.12, Clang с Windows SDK, KiCad 10 и локальный z88dk. Для обычной сборки нужны только Python 3.9 или новее и z88dk. Clang нужен для автоматической проверки на ядре эмулятора; KiCad — для экспорта схемы.

```bat
setup-env.bat
build.bat original all
verify.bat original
```

`setup-env.bat` устанавливает компилятор в `.tools/z88dk-2.4/z88dk`. При отсутствии установки скачивается [официальный архив z88dk 2.4](https://github.com/z88dk/z88dk/releases/tag/v2.4); перед распаковкой проверяется SHA256 из `tools/toolchain.json`. Размер загрузки около 118 МБ. Повторный запуск использует установленную версию. Python должен быть доступен как `python`.

Скрипты работают из любой текущей папки, если вызвать `.bat` по полному пути. Исходники компилируются в отдельной рабочей папке внутри `build`, чтобы временные файлы не попадали в исходники и разные варианты не мешали друг другу.

## Команды

```bat
build.bat original hardware
build.bat original emulator
build.bat original all
new-variant.bat clock-fixed original
build.bat clock-fixed all
verify.bat clock-fixed
run-emulator.bat build\clock-fixed\emulator\emulator.bin
```

`new-variant.bat` не перезаписывает существующий вариант. Для основы, отличной от `original`, требуется `variants/<основа>/READY.md`. Это отметка завершённой работы, которую создаёт соответствующий диалог после проверки. `BASE.json` хранит название основы и контрольные суммы скопированных исходников.

Исходники нового варианта располагаются в `variants/<имя>/src`. Список компилируемых файлов задаётся в `variants/<имя>/build.json`; при добавлении модуля обновите массив `sources`. Поле `options` позволяет добавлять необходимые параметры компилятора. CPU и модель ROM остаются фиксированными: `-m8080`, `CRT_MODEL=2`.

## Результат сборки

`build/<имя>/hardware/rom.bin` — полный линейный образ ROM длиной ровно 32 768 байт, загрузка с 0000h, заполнение свободного хвоста `FF`. Записывайте его как бинарный файл в 27C256. Дополнительная обработка адресов не требуется.

`build/<имя>/emulator/emulator.bin` имеет ту же длину, но собирается с `EMU=1`: время читается и записывается через порты 30h–36h комплектного эмулятора. Эту сборку нельзя использовать вместо аппаратной на плате.

Дополнительно сохраняются:

- `build.log` — сообщения компилятора;
- `clock80.map` — адреса функций, секций и переменных;
- `build.json` — размер занятого ROM, свободное место, раскладка RAM, SHA256 образа и исходников, команда сборки;
- `work-<идентификатор>` — копия исходников, листинги, несжатые сегменты и внутренний файл `clock80.rom`.

Для запуска и программатора выбирайте опубликованные `rom.bin` и `emulator.bin`. Внутренний `clock80.bin` содержит только часть образа и не является готовой прошивкой.

Сборка отклоняет ROM больше 32 КБ, неправильное размещение RAM и пересечение статических данных с начальным стеком FE00h. Перед компиляцией удаляются только ранее опубликованные файлы выбранного варианта и цели; при ошибке старый образ не остаётся под видом нового. Размер зазора до стека — не доказательство достаточности стека: максимальную глубину вызовов нужно оценивать отдельно.

## Проверка исполнения

`verify.bat <имя>` собирает небольшой проверочный запускатель на Clang и использует неизменённое ядро `emulator/i8080.c`. Для обеих целей он доходит до `main` и побайтно сравнивает распакованный DATA с результатом компилятора. Для эмуляторной цели дополнительно выполняет 60 миллионов тактов, подаёт тестовое время RTC и сохраняет `screen.ppm` вместе с `verification.txt`.

Это базовая проверка загрузки, LCD и обращений к RTC. Она не проверяет все пункты меню, точность датчиков, электрические задержки или предельное использование стека. Для новых экранов можно добавить собственные проверки в папке варианта; общий тест ожидает работу часов и хотя бы один полный экран записанных пикселей.

Комплектный графический эмулятор моделирует экран, три кнопки и специальные порты RTC. BME280, DS18B20 и звук он не моделирует. Нули и `+0.1` в полях датчиков исходной прошивки при таком запуске не являются измерениями. У эмулятора также неполный перенос календарной даты через полночь и отсутствует запись секунд в порт 30h; это ограничения его исходного кода.

## Изменения для совместимости

- Конфигурация `clock80.cfg` обновлена под z88dk 2.4. Убран устаревший `-M`, который в этой версии означает остановку после подготовки зависимостей.
- CRT использует современные имена включаемых файлов и `crt0_init`. Сохранён исходный распаковщик ZX7 для 8080. Возврат из `main` остаётся в цикле с `DI`, поскольку монитора по адресу F800h на этой плате нет.
- В `firmware/i2c.c` при `EMU` выбирается только виртуальное чтение и запись времени, без предварительных аппаратных транзакций. Ветка для платы сохранена. Это также позволяет уместить эмуляторную сборку в 32 КБ.
- Старые `firmware/make*.bat` сохранены как часть исходного комплекта; рабочая команда новой среды — корневой `build.bat`.

Существующие `full.bin` и `full_116.bin` сохранены как исходные готовые образы. Совпадение новой сборки с ними побайтно не ожидается: версия компилятора, CRT и упаковка отличаются.
